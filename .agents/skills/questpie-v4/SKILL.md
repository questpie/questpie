# QUESTPIE v4 router

Read `HANDOFF.md` first. It names the accepted outcome, exact heads, dirty-state
constraints, active frontier, and latest verification. Then load exactly one
branch:

- Product design, architecture, public interface, ADR, or wayfinder work: read
  [design.md](references/design.md).
- Focused proof construction or acceptance review: read
  [proof.md](references/proof.md).
- Production implementation, bug fix, or code review: read
  [implementation.md](references/implementation.md).
- Finished-product public documentation: read
  [public-documentation.md](references/public-documentation.md).
- Repository scripts, tests, benchmarks, CI, dependencies, security, or release:
  read [repository-quality.md](references/repository-quality.md).

Load a second branch only when the task genuinely crosses it. Use repository
documents and package scripts as authority; personal skill paths are never a
repository dependency.
