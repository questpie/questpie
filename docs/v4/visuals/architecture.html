01 / The reset

V3 evidence. V4 architecture.

V3 proved valuable behavior. It also made composition, ownership, and TypeScript harder to see. V4 keeps the guarantees and removes the hidden machinery.

V3: runtime composition

  • Modules merge at runtime.
  • Import order can select behavior.
  • Equal names have unclear ownership.
  • User grows through hidden expand or merge steps.
  • Admin extends backend builders.
  • ORM types leak into public contracts.
  • Host adapters multiply lifecycle tests.

V4: compiled application

  • Compiler resolves the complete application before startup.
  • Every resource has identity, Owner, and Origin.
  • Only an authorized Augmentation can change a resource.
  • Collisions fail with both source locations.
  • Studio uses the public App Contract.
  • Generated declarations contain no ORM identity.
  • The Runtime owns one lifecycle and one Fetch seam.
02 / Static composition

One downward pipeline

The Runtime does not discover structural plugins. It loads compiler output.

SOURCE

Definitions

Collections, Fields, Policy, Query, Mutation, Action, Route, Services, and durable handlers.

COMPOSE

Identity graph

Owner, Origin, authorized Augmentation, references, collisions, and deterministic order.

GENERATE

Concrete artifacts

Compiled Manifest, Origin Map, Migration Plan, App Contract, and client contract.

EXECUTE

PostgreSQL Runtime

Operations, transactions, dispatch, Change Ledger, Live Query, events, and Studio.

Same-Primitives Law: first-party code, a package, and application code enter the same normalized identity and ownership model.
03 / Ubiquitous language

One name for one concept

Name Meaning Do not use as a synonym
Definition A declarative source value that the compiler can identify and normalize. Module, plugin root, registry entry
Feature A userland folder that groups related source. It has no runtime semantics. Module, Slice, Feature Kit
Package A distribution unit. Installation does not activate its Definitions. Auto-loaded plugin
Owner The one Definition that creates a resource. Last writer
Origin The exact package, file, and export that supplied an input. Filename-derived identity
Augmentation A contribution accepted through the Owner's explicit contract. Merge, expand, patch
Capability A product inventory label only. Public composition root
Studio The operational inspector for a compiled application. CMS Admin, Operator App framework

Collision in v3

starter/users.ts and booking/users.ts can depend on merge order. A reader must inspect both modules and the merge implementation.

Collision in v4

The compiler reports one identity, two Origins, both Owners, and the missing Augmentation authority. Startup never chooses a winner.

Compiler proof

  • appointments has one stable identity.
  • The booking Package owns it.
  • A reminder Package adds one legal Augmentation.
  • A second Owner produces a hard collision.
  • The Origin Map shows each input.

Transaction proof

  • Mutation updates an appointment.
  • The same commit writes Change Ledger and Reaction intent.
  • Lost response and duplicate delivery do not duplicate the change.
  • An unsafe external Service cannot run in a retryable transaction.

Realtime proof

  • The Runtime records reads that the Query actually executes.
  • Policy, Tenant, Relation, order, and page boundary reads participate.
  • Recompute replaces the dependency set.
  • Raw SQL requires a dependency token.
  • Each Live Query converges independently.

PostgreSQL proof

  • A committed migration produces the expected fingerprint.
  • Raw SQL, cascades, and an external writer enter reconciliation.
  • A crash before wake loses no refresh or Reaction.
  • Local and managed provider profiles run the same conformance suite.

Operational proof

  • Direct call, network client, and Studio return the same authorized result.
  • Append-only runtime events share one correlation schema.
  • Execution and subscription limits fail explicitly.
05 / TypeScript boundary

Generate the application type. Do not infer the universe.

V3 pressure

// Conceptual failure mode
Questpie<
  MergeModules<
    ExpandCollections<
      DrizzleTableGenerics<...>
    >
  >
>

Recursive whole-app inference repeats work. ORM identity crosses package boundaries. Duplicate dependencies can cause deep incompatibility or any.

V4 generated contract

// Shape only. Names are not locked.
type AppContract = {
  queries: {
    appointments: {
      input: AppointmentQueryInput
      output: AppointmentPage
      errors: AppointmentQueryError
    }
  }
}

The compiler writes concrete keys and leaf types. The normal declaration file contains no Drizzle or Kysely symbols.

Exact TypeScript output does not validate runtime values by itself. The operation grill must define when the compiler emits a runtime schema and when the author supplies one.
06 / Data and execution

PostgreSQL is part of the guarantee

Mutation

Owns one PostgreSQL transaction and the atomic durable-dispatch boundary.

Change Ledger

Stores committed reactive changes. A lossy wake only announces possible progress.

Reaction

Runs at least once after commit with stable causation and idempotency identity.

07 / Operational surface

Studio explains the application

A database console can show rows. Studio shows why an application changed and what the Runtime did next.

Composition

Manifest, identity, Owner, Origin, Augmentation, package, and collision diagnostics.

Schema

Migration Plan, checksums, apply history, Schema Fingerprint, drift, and Seeds.

Execution

Operation, Principal, Tenant, Policy decision, transaction, error, duration, and limits.

Durability

Dispatch, Reaction, Job attempt, lease, retry, dead letter, and causation.

Realtime

Observed reads, ledger cursor, wake reason, lag, recompute, reconnect, and recovery.

Telemetry

Append-only events with one versioned Execution Envelope correlation schema.
