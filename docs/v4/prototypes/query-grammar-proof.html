Throwaway semantic simulator · not a protocol golden or production API

Can one closed query shape survive the awkward cases?

Drive a small Barbershop page query, inspect every normalized byte-level fact, and try the cases that tend to break cursor and dependency models. This simulator uses a page limit of four and computes its own Query digest; it does not claim the exact digest pinned by the separate executable golden.

Question: Can exact selection, filtering, stable ordering, forward pagination, and one-hop Relation traversal share one closed Query model with deterministic canonical bytes and a complete declared dependency template?
