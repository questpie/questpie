## Non-blocking observations

1. `QP-COMPOSE-004 unknownReference` is not implemented, and relations are in scope for this slice. `relationRef()` returns a template-literal type over any string, and `projectManifest` (`model.ts`) emits `references: ["collection:<target>/field:<name>"]` with no lookup of the target Collection or Field. `relationRef("nonexistant")` therefore produces a Compiled Manifest and Schema Projection containing a dangling identity that nothing rejects. The fixture exercises four relations, and BETA-02 consumes these bytes as foreign keys, so this should be closed before #289 rather than inherited.
2. Package resolution is directory-shaped. `resolveWorkspacePackages()` scans `<applicationRoot>/packages/*` rather than resolving the activated name through node/Bun package resolution. It does validate `type`, `version`, `questpie.manifestVersion`, and the `./questpie` export target, but a normally installed registry Package would not resolve at all. Related: `QP-COMPOSE-007 incompatiblePackage` is never raised — `manifest.questpie.framework` is read into the type but never range-checked.
3. `resolvePackages` hashes every file under the Package root via `packageFiles()`, including any `dist/`, `node_modules/`, or stale `.questpie/` content. That widens `PackageResolutionV1.contentDigest` beyond the activation graph and can make `resolutionDigest` environment-sensitive for a built or locally installed Package.
4. `postgres.minimumMajor` is validated as exactly `16`. `configuration()` rejects any other value even though `beta1-build-spec.md` and Gate 8A target PostgreSQL 17. Nothing in the accepted root schema makes this a constant.
5. Purity scanning is syntactic and has known holes. `globalThis.process.env.X` is not caught (the `process` identifier check excludes property-access names), and `performance.now()`/`Date.parse` are neither scanned nor stubbed in the runner. The empty child environment mitigates the first case, but the boundary is best-effort rather than the closed capability list in `definition-composition.md`.
6. The second compilation does not use a different synthetic checkout root. The accepted contract requires reversed order and relocation inside the two-run proof; relocation is proved separately in `tests/type/beta01-generated-contract.test.ts`, which is equivalent evidence but not the specified mechanism.
7. Single-Package typechecking is not program-isolated. In `typecheck.ts`, when exactly one Package is active its source files and `#questpie/package` mapping are folded into the application program; with two or more, isolated per-Package programs are emitted. Isolation currently rests on the syntactic `QP-COMPOSE-012` check plus the specialized contract content, not on program separation. Making both paths use isolated programs would remove the branch.
8. `write.ts` backup/restore is unreachable in practice. Every failure path in `compileApplication` precedes `replaceGeneratedDirectory`, so the `rename(backup, outputDirectory)` recovery has no test.
9. Diagnostic registry remains partial. `diagnostic.ts` implements 12 of the 22 closed composition codes and no `QuestpieDiagnosticBaseV1` envelope (`severity`, `blocking`, `origins`, `recovery`). `QP-COMPOSE-001`, `003`, `016`, `018`, `019`, `021`, and `022` are absent, and Qualified Resource Name grammar is unvalidated. Consistent with ADR-0020 naming Bun 1.3.14 as repository authority, but the golden will break on any Bun bump and the failure will read as a compiler regression.
