## Non-blocking observations

**1. `QP-COMPOSE-013 structuralTypeError` is used as a catch-all for composition-graph errors** — `packages/compiler/src/composition/index.ts` emits it for dependency cycles, invalid lifetime edges, invalid effect edges, and "more than one Context". The closed registry in `docs/v4/definition-composition.md` documents 013's trigger as "A candidate module or structural dependency has a TypeScript error." The emitted `code`/`class` pair is in the closed registry (unlike the `unresolvedReference` spelling this PR correctly removed), so this is not a registry violation, but the trigger semantics do not match. The registry has no code for an invalid composition graph; closing that gap needs a doc/ADR revision outside BETA-03's authority. Worth an explicit follow-up rather than silent reuse.

**2. `contextProjection` hardcodes `owner: { kind: "application" }`** (`composition/index.ts`) while the service projection derives owner from `resource.origin.packageId`. A Package-defined Context is currently rejected earlier by `packageContract` in `model.ts`, so the claim is true today, but the asymmetry is a latent false-ownership hazard if that guard ever moves.

**3. Application-lifetime Service creation failures are cached permanently.** `applicationCells.set(identity, created)` in `packages/runtime/src/execution/index.ts` stores the rejected promise, so one transient `create` failure poisons that Service for the Runtime instance's remaining life. The execution-scope path is unaffected (per-root cells). ADR-0015 does not specify failure-cache behaviour; worth deciding explicitly before BETA-05.

**4. Generated `app.ts` now embeds Origin logical paths and export names** via `#questpie/source/<path>` in `renderAppContract`. The accepted relocation invariant is preserved as tested (the determinism protocol relocates the synthetic checkout root while preserving logical paths, and `app.ts` is not a semantic artifact), but moving a Definition *within* `src/` now changes generated bytes. Consider an explicit intra-source relocation case so the boundary is asserted rather than assumed.

**5. Compiler projection and Runtime program are not joined by any test.** The integration test compiles the fixture only to assert `service-projection.json` and `context-projection.json` exist, then hand-builds `createApplicationRuntime({ services: [auditConnection, executionAudit], ... })`. Nothing proves the runtime's Service set or Context matches the compiled projection. This is consistent with "a complete generated Runtime Build remains out of scope," but the seam carries real risk into BETA-05.

**6. `copiedFrozen` uses `structuredClone` on the resolved Context.** Prototypes are dropped and non-cloneable values throw. Fine for plain data (both fixtures), but the failure mode is an opaque `DataCloneError` at root construction rather than a typed Context diagnostic.

**7. `context.*` grammar is not exported.** `docs/v4/context-and-policy.md` spells resolution as `context.tenant({ id })` and `context.error.notFound(...)`, and ADR-0019 lists `context` among the retained restricted grammars. The implementation accepts a plain `{ id: string }` and `principal` is exported while `context` is not. Not claimed by any BETA-03 criterion and the docs-vs-surface gate is BETA-12, but it is a public-surface divergence to close.

**8. `effect: "read" | "external"` vs ADR-0015's "transaction-safe or external-effect" wording.** ADR-0015 explicitly leaves final spelling to ticket #21, so this is in bounds; noting it so the rename is not lost.

**9. `canonicalBytes(serviceProjection)` / `canonicalBytes(contextProjection)` results are discarded** in `projectExecutionComposition`. If the intent is an early canonicalizability check, make it an assertion; otherwise remove it — as written it reads as dead code.

**10. `ExecutionServices` exposes every application-owned Service regardless of effect class.** ADR-0015 requires that Query and Mutation contexts cannot reach external-effect Services. No Query/Mutation context exists yet, so nothing is violated, but the transaction-safe partition must land with BETA-04/BETA-06 rather than being inherited from this flat map.

**11. `QUEUE.json` marks BETA-03 `agentReady: false`.** The packet contains no record of the readiness promotion. If a promotion decision exists, referencing it in the acceptance manifest would close the governance loop.

**12. Test imports bypass package boundaries.** `tests/integration/beta03-execution-services.test.ts` imports `../../packages/runtime/src` and `tests/unit/beta03-service-composition.test.ts` imports `../../packages/compiler/src/composition`, so the newly added `@questpie/runtime` exports map is not exercised by any test.
