title: Hooks

Hooks let you run logic at specific points in the collection lifecycle. They receive the full typed `AppContext` through context injection — no imports needed.

<Callout type="info">For the complete hook execution order diagrams, all hook type signatures, and full context property tables, see the [Hooks API Reference](/docs/reference/hooks-api).</Callout>

## Hook Lifecycle

For a create or update operation, hooks run in this order:

```
beforeOperation → beforeValidate → Schema Validation → beforeChange → DB Write → afterChange → afterRead
```

For a delete:

```
beforeOperation → beforeDelete → DB Delete → afterDelete
```

## Defining Hooks

```ts title="collections/appointments.ts"
.hooks({
  beforeValidate: async (ctx) => {
    // Modify data before validation
    if (ctx.data.name && !ctx.data.slug) {
      ctx.data.slug = slugify(ctx.data.name);
    }
  },

  beforeChange: async ({ data, operation }) => {
    if (operation === "create") {
      // Set defaults on create
    }
    if (operation === "update") {
      // Mutate data before DB write
    }
  },

  afterChange: async ({ data, operation, original, queue }) => {
    if (operation === "create") {
      await queue.sendAppointmentConfirmation.publish({
        appointmentId: data.id,
        customerId: data.customer,
      });
    }

    if (operation === "update" && original) {
      if (data.status === "cancelled") {
        await queue.sendAppointmentCancellation.publish({
          appointmentId: data.id,
          customerId: data.customer,
        });
      }
    }
  },

  beforeDelete: async ({ id }) => {
    // Prevent deletion or clean up
  },

  afterDelete: async ({ id }) => {
    // Clean up related data
  },
})
```

## Hook Context

Every hook receives the full `AppContext` via destructuring. Hook-specific properties (`data`, `operation`, `original`, `fromStage`, `toStage`, etc.) are available alongside shared context properties (`db`, `collections`, `globals`, `queue`, `email`, `session`, and any custom services from `services/`).

<Callout type="info">See the [Hooks API Reference](/docs/reference/hooks-api) for the complete per-hook context property tables.</Callout>

## Context-First Pattern

Hooks use context-first injection. All dependencies are available through destructuring — no need to import the app instance:

```ts title="collections/blog-posts.ts"
.hooks({
  beforeChange: async ({ data, services }) => {
    // `services.blog` is a custom service from services/blog.ts
    const { blog } = services;
    data.slug = blog.generateSlug(data.title);
    data.readingTime = blog.computeReadingTime(data.content);
    data.excerpt = blog.extractExcerpt(data.content);
  },

  afterChange: async ({ data, operation, original, queue }) => {
    // Publish job when status transitions to "published"
    if (
      operation === "update" &&
      original?.status !== "published" &&
      data.status === "published"
    ) {
      await queue.notifyBlogSubscribers.publish({
        postId: data.id,
        title: data.title,
        excerpt: data.excerpt,
        slug: data.slug,
      });
    }
  },
})
```

## Real-World Examples

### Auto-generate slug

```ts
.hooks({
  beforeValidate: async (ctx) => {
    if (ctx.data.name && !ctx.data.slug) {
      ctx.data.slug = slugify(ctx.data.name);
    }
  },
})
```

### Send email on status change

```ts
.hooks({
  afterChange: async ({ data, operation, original, queue }) => {
    if (operation === "create") {
      await queue.sendAppointmentConfirmation.publish({
        appointmentId: data.id,
        customerId: data.customer,
      });
    }
    if (operation === "update" && data.status === "cancelled") {
      await queue.sendAppointmentCancellation.publish({
        appointmentId: data.id,
        customerId: data.customer,
      });
    }
  },
})
```

### Compute derived fields

```ts
.hooks({
  beforeChange: async ({ data, services }) => {
    data.readingTime = services.blog.computeReadingTime(data.content);
    data.excerpt = services.blog.extractExcerpt(data.content);
  },
})
```

## Multiple Hook Functions

Each hook type accepts an array of functions. They execute in order:

```ts
.hooks({
  afterChange: [
    async ({ data }) => { /* first handler */ },
    async ({ data }) => { /* second handler */ },
  ],
})
```

Multiple `.hooks()` calls on the same builder merge their handlers — useful for splitting concerns across mixins or plugins:

```ts
collection("posts")
  .hooks({ afterChange: handler1 })
  .hooks({ afterChange: handler2 });
// Both handler1 and handler2 will run
```
