## `global(name)`

Creates a new global builder. A global is a singleton record — one row per global, used for site settings, configuration, and other single-instance data.

---

## Builder Methods

All methods are chainable and return a new builder instance. Globals do **not** support `.list()`, `.indexes()`, `.title()`, or `.preview()`.

| Method       | Description                                             |
| ------------ | ------------------------------------------------------- |
| `.fields()`  | Define data fields using the field builder              |
| `.options()` | Configure schema, timestamps, versioning, scoped mode   |
| `.hooks()`   | Attach lifecycle hooks                                  |
| `.access()`  | Set access control rules                                |
| `.set()`     | Generic extension point for plugins                     |
| `.admin()`   | Admin UI metadata (label, icon) — requires `@questpie/admin` |
| `.form()`    | Configure the admin form view — requires `@questpie/admin`   |

---

## `.fields(callback)`

Define global fields using the field builder. See [Field API](/docs/reference/field-api) for all field types and chain methods.

```ts
.fields(({ f }) => ({
  siteName: f.text(255).required(),
  description: f.textarea().localized(),
  logo: f.upload(),
  theme: f.select([
    { value: "light", label: "Light" },
    { value: "dark", label: "Dark" },
    { value: "system", label: "System" },
  ]).default("system"),
  analytics: f.object(),
}))
```

---

## `.options(config)`

Configure global-level options.

```ts
.options({
  schema: "web",          // Postgres schema for all tables (default: public)
  timestamps: true,       // Adds createdAt, updatedAt (default: true)
  versioning: true,       // Creates a versions table for history
  scoped: true,           // Scope globals by scope_id (multi-tenant)
})
```

| Option         | Type                        | Default    | Description                                                          |
| -------------- | --------------------------- | ---------- | -------------------------------------------------------------------- |
| `schema`       | `string`                    | `"public"` | Postgres schema for the global's tables. `migrate:generate` emits `CREATE SCHEMA IF NOT EXISTS` on first use. |
| `timestamps`   | `boolean`                   | `true`     | Adds `createdAt` and `updatedAt` columns.                            |
| `versioning`   | `boolean \| VersioningConfig` | `false`  | Creates a versions table. Pass an object to configure workflow.      |
| `scoped`       | `boolean`                   | `false`    | Stores one row per `scope_id` instead of a single global row.        |

When `scoped` is enabled, the global stores one row per scope instead of a single global row.

### Versioning with Workflow

```ts
.options({
  versioning: {
    enabled: true,
    workflow: {
      stages: ["draft", "published"],
      initialStage: "draft",
    },
  },
})
```

## `.hooks(config)`

Attach lifecycle hooks. See [Hooks API](/docs/reference/hooks-api) for all hook types and context properties.

```ts
.hooks({
  beforeChange: ({ data }) => {
    if (data.siteName) {
      data.siteName = data.siteName.trim();
    }
  },
  afterChange: async ({ data, kv }) => {
    // Invalidate cache when settings change
    await kv.delete("site-settings-cache");
  },
})
```

---

## `.access(config)`

Set access control rules. Globals support `read` and `update` operations (no create/delete since they are singletons).

```ts
.access({
  read: true,
  transition: ({ session }) => session?.user?.role === "editor",
  update: ({ session }) => session?.user?.role === "admin",
})
```

`transition` controls workflow stage transitions. If it is omitted, workflow transitions fall back to the `update` rule.

---

## `.set(key, value)`

Generic extension point for plugins to attach metadata.

```ts
.set("admin", { icon: { type: "icon", props: { name: "ph:gear" } } })
```

---

## Admin Extension Methods

### `.admin(callback)`

Set admin UI metadata for the global.

```ts
.admin(({ c }) => ({
  label: { en: "Site Settings" },
  icon: c.icon("ph:gear"),
}))
```

### `.form(callback)`

Configure the admin form view.

```ts
.form(({ v, f }) => v.globalForm({
  fields: [
    f.siteName,
    f.tagline,
    {
      type: "section",
      label: "Appearance",
      fields: [f.logo, f.theme],
    },
  ],
}))
```

## Server API

```ts
const settings = await globals.siteSettings.get();
console.log(settings.siteName);

await globals.siteSettings.update({
	siteName: "New Site Name",
	theme: "dark",
});
```

With localized fields, pass a locale:

```ts
const settings = await globals.siteSettings.get({ locale: "sk" });
await globals.siteSettings.update({ tagline: "Novy slogan" }, { locale: "sk" });
```

---

## Client API

```ts
const settings = await client.globals.siteSettings.get();
await client.globals.siteSettings.update({ siteName: "Updated" });
```

With workflow enabled, `get()` and `update()` accept `stage`:

```ts
const published = await client.globals.siteSettings.get({
	stage: "published",
});

await client.globals.siteSettings.update(
	{ announcement: "Launching soon" },
	{ stage: "draft" },
);
```

---

## Workflow Transition API

`transitionStage()` moves a global to a target workflow stage without mutating the working row.

```ts
await globals.siteSettings.transitionStage({
	stage: "published",
});
```

The client SDK supports the same call, including scheduled transitions:

```ts
await client.globals.siteSettings.transitionStage({
	stage: "published",
	scheduledAt: new Date("2026-05-01T09:00:00Z"),
});
```

Validation rules: target stage must exist, the transition graph must allow the move, `access.transition` must pass (or falls back to `access.update`), and transition hooks run around the version snapshot.

---

## Type Inference

Globals provide type inference through `$infer`:

```ts
type SettingsSelect = typeof siteSettings.$infer.select;
type SettingsInsert = typeof siteSettings.$infer.insert;
type SettingsUpdate = typeof siteSettings.$infer.update;
```

<Accordion title="GlobalOptions">
```ts
interface GlobalOptions {
  /** Postgres schema for all tables. Defaults to "public". */
  schema?: string;
  /** Add createdAt and updatedAt columns. Defaults to true. */
  timestamps?: boolean;
  /** Enable version history. Pass true or a VersioningConfig object. */
  versioning?: boolean | VersioningConfig;
  /** Store one row per scope_id instead of a single global row. */
  scoped?: boolean;
}

interface VersioningConfig {
  enabled: boolean;
  workflow?: {
    stages: string[];
    initialStage: string;
    transitions?: Record<string, string[]>;
  };
}
```
</Accordion>
<Accordion title="GlobalAccessConfig">
```ts
interface GlobalAccessConfig {
  /** Allow/deny read. Use a function for session-based rules. */
  read?: boolean | ((ctx: AccessContext) => boolean | Promise<boolean>);
  /** Allow/deny update. */
  update?: boolean | ((ctx: AccessContext) => boolean | Promise<boolean>);
  /** Allow/deny workflow stage transitions. Falls back to update if omitted. */
  transition?: boolean | ((ctx: AccessContext) => boolean | Promise<boolean>);
}

interface AccessContext {
  session: Session | null;
  req: Request;
}
```
</Accordion>
<Accordion title="GlobalRuntime — get / update / transitionStage">
```ts
interface GlobalRuntime<T> {
  /** Read the current global value. */
  get(options?: { locale?: string; stage?: string }): Promise<T>;
  /** Update the global value. Returns the updated record. */
  update(data: Partial<T>, options?: { locale?: string; stage?: string }): Promise<T>;
  /** Transition the global to a workflow stage. */
  transitionStage(options: {
    stage: string;
    scheduledAt?: Date;
  }): Promise<void>;
}
```
