| Surface               | Detail                                                      |
| --------------------- | ----------------------------------------------------------- |
| Signature             | `f.json<T>(config?)`                                        |
| Config                | `{ mode?: "jsonb" \| "json" }`, optional                    |
| Column                | `jsonb`, or `json` under `{ mode: "json" }`                 |
| Schema                | a recursive JSON union, not `z.any()`                       |
| Filter operators      | six, every one against the whole value, [below](#filtering) |
| Admin form            | a monospace textarea with a Format button                   |
| Admin cell            | fifty characters, the whole value in a `title` attribute    |
| Type-specific methods | none, the shared chain is the whole surface                 |

```ts title="src/questpie/server/collections/posts.ts"
import { collection } from "#questpie/factories";

export const posts = collection("posts").fields(({ f }) => ({
	metadata: f.json(), // any JSON value
	settings: f.json<{ theme: "light" | "dark" }>(), // narrowed
}));
```

`metadata` reads back as `JsonValue | null`, `settings` as
`{ theme: "light" | "dark" } | null`. Both are one `jsonb` column, no second
table and no join. `JsonValue` is exported from `questpie`.

Reach for it when the shape is genuinely open. When the keys are fixed,
[`f.object()`](/docs/schema/fields/object) takes the same column and gives every
key its own schema, label, locale and access rule, plus eleven structural filter
operators this type does not have.

## The mode

| Call                        | Column  |
| --------------------------- | ------- |
| `f.json()`                  | `jsonb` |
| `f.json({ mode: "jsonb" })` | `jsonb` |
| `f.json({ mode: "json" })`  | `json`  |

The derived schema and the operator set are identical in both. The argument
moves the Postgres column type and nothing else.

## Typing the value

The type argument, `.$type()` and `.zod()` all move the value type. Where they
part company is the filter and the runtime check.

| Form          | Read type           | Filter operand | Runtime check  |
| ------------- | ------------------- | -------------- | -------------- |
| `f.json()`    | `JsonValue \| null` | `JsonValue`    | the JSON union |
| `f.json<T>()` | `T \| null`         | `T`            | the JSON union |
| `.$type<T>()` | `T \| null`         | unchanged      | the JSON union |
| `.zod(fn)`    | the schema output   | unchanged      | the schema     |

The field fixes its filter operand when the factory runs, so unchanged means
whatever the type argument said, `JsonValue` when you passed none. A later
`.$type()` or `.zod()` cannot reopen it.

`.zod()` narrows the read type only when the schema it returns has a real output
type. Return a bare `ZodType` and the field keeps the type it had, with the new
validation on top.

```ts
import { z } from "zod";

preferences: f
	.json<{ theme: "light" | "dark"; density: number }>()
	.zod(() =>
		z.object({
			theme: z.enum(["light", "dark"]),
			density: z.number().int().min(1).max(5),
		}),
	)
	.required(),
```

<Callout type="warn" title="A type argument alone accepts anything">
	`f.json<{ theme: "light" | "dark" }>()` moves the TypeScript type and leaves the
	schema as the loose JSON union, so a write of `{ theme: "blue" }` is stored. Add
	`.zod()` to make the shape a rule.
</Callout>

Without `.required()` the column is nullable and the input optional. The derived
schema is the recursive union of `string`, `number`, `boolean`, `null`, arrays
and objects, so a `Date`, a `Map` or a function fails validation instead of
passing through.

## Filtering

The JSON field carries the basic operator set. Every entry compares the stored
value as a whole.

| Operator               | Operand               | Matches                       |
| ---------------------- | --------------------- | ----------------------------- |
| `eq` / `ne`            | the whole value       | Equal, not equal              |
| `in` / `notIn`         | array of whole values | In the list, not in the list  |
| `isNull` / `isNotNull` | `boolean`             | Pass `false` and each inverts |

```ts
const { docs } = await app.collections.posts.find({
	where: { settings: { eq: { theme: "dark" } } },
});

await app.collections.posts.find({
	where: { metadata: { isNull: true } },
});
```

The set carries a seventh operator, `not`, which the field's declared filter
input leaves out. It runs, and it does not type-check.

<Callout type="warn" title="A key filter is dropped, not rejected">
	`where: { settings: { theme: "dark" } }` type-checks, because any JSON object is
	also a valid whole-value shorthand. QUESTPIE finds no operator in it, compiles
	nothing, and returns every row. Use `eq`, or model the key with `f.object()`.
</Callout>

An operator object is recognized by its keys, so a stored object whose own top
level key is called `eq`, `in` or `not` is ambiguous to the same check.

## Lists

A JSON value is already allowed to be an array, so a list needs no `.array()`.
Say so in the type argument.

```ts
tags: f.json<string[]>(),
events: f.json<Array<{ at: string; type: string }>>(),
```

<Callout type="warn" title="`.array()` splits the filters in two">
	It swaps the runtime operator set for the array one, `containsAll`,
	`containsAny`, `length` and the rest, while the field keeps the JSON filter
	input it declared. What you can type and what runs stop agreeing.
</Callout>

## Localization

`.localized()` moves the whole value into the i18n table, one JSON document per
locale. There is no per-key split here, because there are no declared keys. A
write replaces that locale's document outright.

The control renders no locale indicator. `JsonField` builds its own label row
and never reads the `localized` prop. Storage is unaffected.

## In the admin

The form control is `JsonField`. It prints the stored value with a two space
indent into a monospace textarea and parses on every keystroke. A draft that
does not parse is written to the form as the raw string and validation refuses
it. Emptying the box writes `null`. The Format button reprints the value.

The list cell is `JsonCell`. Compact JSON, cut at fifty characters, the whole
value in a `title` attribute, a dash when null.

`.admin()` reaches the control:

| Option            | Values                   | Default  |
| ----------------- | ------------------------ | -------- |
| `minHeight`       | pixels                   | `200`    |
| `maxHeight`       | pixels, `0` for no limit | `400`    |
| `defaultMode`     | `"code"`, `"form"`       | `"code"` |
| `allowModeSwitch` | boolean                  | `true`   |

The last two are inert on a declared field. Both feed a second editing mode that
renders only when the control is also handed a `renderForm` render prop, and
field metadata crosses to the browser as JSON, so a collection file has no way
to send a function. `JsonFieldAdminMeta` also declares a `codeEditor` flag that
nothing reads.
