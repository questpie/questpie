This page shows you that description and what comes out of it. Three minutes,
and you do not have to install anything to follow along.

## The file you write

One file, in `src/questpie/server/collections/`. Nothing registers it; the
filename is the registration.

```ts title="src/questpie/server/collections/news.ts"
import { collection } from "#questpie/factories";

export const news = collection("news")
	.fields(({ f }) => ({
		title: f.text(255).label("Title").required(),
		content: f.richText(),
		isPublished: f.boolean().default(false),
	}))
	.title(({ f }) => f.title);
```

Three fields, and a `.title()` telling the admin which one to show as the label
of a row. That is the whole definition.

## What comes out of it

Run the generator once:

```bash
questpie generate
```

You now have four things you did not write:

- **A typed object.** `app.collections.news.find()`, `.create()`,
  `.updateById()` — with your field names on them, so a typo is a compile error.
- **Five REST routes.** `GET /api/news`, `GET /api/news/:id`, `POST /api/news`,
  `PATCH /api/news/:id`, `DELETE /api/news/:id`.
- **An admin screen.** A list with your labels, and a form with the right
  control for each field type — a text input for `text`, an editor for
  `richText`, a switch for `boolean`.
- **A typed client.** `client.collections.news.find()` in your frontend, with
  the same types the server has.

Change `f.text(255)` to `f.text(500)` and re-run the generator. All four follow.
Nothing is defined twice, so nothing can drift.

## What you still write yourself

QUESTPIE derives the plumbing around your data. It does not write your product.

- **Your pages.** QUESTPIE gives you a typed client, not a frontend.
- **Your business rules.** Who may read what is a rule you declare; what
  "published" means for your company is code you write.
- **Anything with an opinion.** Pricing, workflows, the words on your buttons.

If you were hoping for a CMS that builds the site too, this is not that. It is
the layer underneath one.

## What it runs on

- **Bun 1.3+** — the runtime the template targets.
- **PostgreSQL 15+** — the minimum database version.
- **MIT, on your servers.** There is no hosted tier to graduate to.
