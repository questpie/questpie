Every QUESTPIE read query has a live form. Broadcasts are automatic — every collection and global create/update/delete already emits a change event server-side (outbox pattern), so there is nothing to wire up in hooks. Subscribe to a query and the server pushes fresh, access-controlled results whenever matching data changes.

Do **not** write `afterChange` hooks that "emit" realtime events — the built-in broadcast hook already covers every CRUD operation, and a custom emitter double-fires.

## How It Works

1. Every CRUD write appends a change event to the `questpie_realtime_log` outbox and notifies subscribers (via the configured [realtime adapter](/docs/production/realtime), or 2s polling with zero config).
2. For each affected subscription, the server **re-runs the subscribed query under the subscriber's auth context** and pushes the full result as a `snapshot` event. Clients never receive raw change events — snapshots are access-controlled by construction.
3. One SSE connection multiplexes all topics (`POST /realtime`), so any number of live queries share a single HTTP connection.

Snapshots are idempotent state, not diffs. Updates and deletes against filtered subscriptions may push snapshots whose content did not change (over-refresh by design) — always render from the snapshot, never accumulate.

## Live Queries

`live()` is the live form of `find()` — same options in (typed `where`/`with`/`orderBy`), same result type out. The first snapshot arrives immediately on connect, so no separate initial fetch is needed.

```ts
import { client } from "@/lib/client";

// Typed: where keys/values and the snapshot shape are inferred from the schema
const stop = client.collections.posts.live(
	{
		where: { status: "published" },
		with: { author: true },
		orderBy: { createdAt: "desc" },
		limit: 50,
	},
	(snapshot) => {
		renderFeed(snapshot.docs); // snapshot.docs[i].author is typed
	},
	{ onError: (error) => console.error(error) },
);

// Later: unsubscribe
stop();
```

Live options carry exactly what the wire protocol supports: `where`, `with`, `limit`, `offset`, `orderBy`, `locale`. Options that change the result shape locally (`columns`, `groupBy`, `search`) are not part of the live contract and are rejected at compile time.

### Async Iteration

`liveIter()` yields the same snapshots as an `AsyncGenerator` — for workers, agents, and tests:

```ts
const controller = new AbortController();

for await (const snapshot of client.collections.posts.liveIter(
	{ where: { status: "published" } },
	{ signal: controller.signal },
)) {
	console.log(snapshot.totalDocs);
}
// controller.abort() terminates the loop
```

### Globals

Globals mirror `get()`:

```ts
client.globals.siteSettings.live(undefined, (settings) => {
	applyTheme(settings);
});

// With relations
client.globals.siteSettings.live({ with: { logo: true } }, (settings) => {
	render(settings.logo.url);
});
```

## React via TanStack Query

Pass `{ realtime: true }` as the typed second argument to `find()`, `count()`, or `get()` builders — initial data comes from a normal fetch, then snapshots stream in:

```tsx
import { useQuery } from "@tanstack/react-query";
import { q } from "@/lib/queries";

function LiveFeed({ eventId }: { eventId: string }) {
	const { data } = useQuery(
		q.collections.posts.find(
			{ where: { event: eventId }, limit: 50 },
			{ realtime: true },
		),
	);

	return <Feed posts={data?.docs ?? []} />;
}
```

See [TanStack Query](/docs/frontend/tanstack-query) for setup.

## Low-Level Escape Hatch

`client.realtime` is the raw multiplexer surface. Topics are plain objects (never channel strings). Prefer the typed `live()` wrappers — the low-level callback data is untyped:

```ts
const unsubscribe = client.realtime.subscribe(
	{ resourceType: "collection", resource: "posts", where: { status: "published" } },
	(data) => {
		// data: unknown — full find() result snapshot
	},
);

// AsyncGenerator form
for await (const snapshot of client.realtime.stream({
	resourceType: "global",
	resource: "siteSettings",
})) {
	// ...
}

// Tear down the SSE connection and all subscriptions
client.realtime.destroy();
```

Live queries with identical options share one SSE topic — a `live()` call and a `{ realtime: true }` query with the same options deduplicate into a single server subscription.

## Wire Protocol

`POST <basePath>/realtime` is a public, semver-stable contract — safe to consume from non-JS clients.

**Request body:**

```json
{
	"topics": [
		{
			"id": "feed",
			"resourceType": "collection",
			"resource": "posts",
			"where": { "status": "published" },
			"with": { "author": true },
			"limit": 50,
			"offset": 0,
			"orderBy": { "createdAt": "desc" },
			"locale": "en"
		}
	]
}
```

`resourceType` is `"collection"` or `"global"`. For globals, only `where`, `with`, and `locale` apply.

**Response:** an SSE stream (`text/event-stream`) with these events:

| Event      | Payload                  | Meaning                                                            |
| ---------- | ------------------------ | ------------------------------------------------------------------ |
| `snapshot` | `{ topicId, seq, data }` | Full query result (same shape as `find()`/`get()`) under the subscriber's auth |
| `error`    | `{ topicId, message }`   | Topic-level failure (unknown resource, access denied, query error) |
| `ping`     | `{ ts }`                 | Keep-alive (default every 8s)                                      |

**Guarantees:**

- Snapshots are complete query results with access rules re-evaluated on every refresh — the server never forwards raw change payloads to clients.
- `seq` is monotonically non-decreasing per stream.
- Over-refresh is by design: a snapshot may be pushed even when the visible result did not change. Treat snapshots as state, not events.
- Unknown SSE event types must be ignored (forward compatibility — a future `change` descriptor event is reserved).

## Keepalive

The stream sends a `ping` every 8 seconds by default (tunable via `realtime.keepAliveIntervalMs` in `questpie.config.ts`). Anything between client and server that kills idle connections must allow at least that interval.

**Bun:** the default `idleTimeout` of `Bun.serve` is 10s. The default 8s ping survives it, but set it explicitly for headroom:

```ts title="src/index.ts"
import { Hono } from "hono";
import { questpieHono } from "@questpie/hono/server";
import { app } from "#questpie";

const server = new Hono();
server.route("/api", questpieHono(app));

export default {
	port: 3000,
	idleTimeout: 30, // seconds — keep SSE streams alive between pings
	fetch: server.fetch,
};
```

See [Realtime (Production)](/docs/production/realtime) for the full proxy/serverless timeout matrix and adapter setup (`pgNotifyAdapter`, `redisStreamsAdapter`, `cloudflareRealtimeAdapter`).
