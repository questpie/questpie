`questpie.json` is the non-executable Application Root. Create it with
`questpie init --name barbershopSupport`; see [installation](/docs/v4/installation).

| Member                                        | Required value or behavior                                              |
| --------------------------------------------- | ----------------------------------------------------------------------- |
| `$schema`                                     | `https://questpie.dev/schema/application-v1.json`                       |
| `version`                                     | `1`                                                                     |
| `application.name`                            | Stable qualified resource name.                                         |
| `postgres.schema`                             | One explicit application PostgreSQL schema.                             |
| `postgres.minimumMajor`                       | Required PostgreSQL major, at least 16.                                 |
| `postgres.databaseCollation`, `databaseCType` | Exact required database locale.                                         |
| `postgres.extensions`                         | Explicit required extensions.                                           |
| `postgres.physicalNames`                      | Explicit identity-to-physical-name overrides.                           |
| `source.root`                                 | Backend source directory, usually `src`.                                |
| `source.exclude`                              | Additional source-root-relative exclusion patterns.                     |
| `packages`                                    | Directly activated Packages and accepted inventory digests.             |
| `projections`                                 | Optional `openapi: true` and `mcp: true` flags (at least one required). |

Unknown keys are rejected. There is no root `definitions` array.
The [installation chapter](/docs/v4/installation) supplies complete configuration.

## Discovery and identity

Export Definitions from `.ts`, `.tsx`, or `.mts` source under `source.root`.
Files ending in `.d.ts`, test/spec files, and `__tests__`, `__fixtures__`, or
`fixtures` directories are excluded by default. Supported glob tokens are
`*`, `?`, and `**`; negation and brace expansion are unsupported.

Each resource has an explicit kind and name. A name uses lower-camel ASCII
segments separated by dots, with 1–63 characters per segment and at most 255
characters overall. A file move does not change resource identity.
Two Definitions establishing the same kind and name are an error.
A same-kind Operation name cannot be both a callable leaf and a namespace
prefix. Its final segment cannot be `then`.

Keep browser code outside discovery. Structural source cannot read environment,
files, network, time, or random values. Runtime handlers and Service factories
own runtime work. Compilation evaluates structural source deterministically;
it is not a sandbox for hostile dependencies.

## Generated output

Build writes `.questpie/generated/`. The public imports are `#questpie/app`
and `#questpie/client`. The `#questpie/source/*` mapping points to your source.
Do not edit generated files or import generated `internal/` modules.
Run build after changing source; run check to validate the current contract
without replacing generated output. TypeScript alone sees only the last build.

## Packages and Augmentations

Installing a Package does not activate its Definitions. Its fixed `./questpie`
composition export and exact inventory must be accepted in `packages`.
Transitive installation does not activate composition.

`defineCollectionAugmentation` from `questpie` can add Fields, Constraints, and
Indexes. An owning Collection accepts exact values in its literal
`augmentations` tuple. It cannot add relations, replace members, or patch
another Definition by name. Colliding members are errors even if byte-equal.

The CLI does not manage Package inventory acceptance. Ordinary TypeScript
libraries need no composition activation. For reusable framework composition,
use [the ecosystem boundary](/docs/v4/ecosystem) and
[escape hatches](/docs/v4/escape-hatches); do not guess an inventory digest.

## Diagnostics

| Code                     | Recovery                                                  |
| ------------------------ | --------------------------------------------------------- |
| `QP-COMPOSE-002`         | Remove duplicate resource ownership.                      |
| `QP-COMPOSE-008`         | Review the changed Package inventory before accepting it. |
| `QP-COMPOSE-010`         | Move runtime effects out of structural declarations.      |
| `QP-COMPOSE-013`         | Fix the TypeScript error at the reported source.          |
| `QP-COMPOSE-014`         | Remove an Augmentation member collision.                  |
| `QP-COMPOSE-017`         | Correct the Application Root.                             |
| `QP-COMPOSE-023` / `024` | Rename the conflicting Operation or final `then` segment. |
