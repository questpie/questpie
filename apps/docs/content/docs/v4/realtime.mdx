A supported generated Query has `.watch(input, onValue, options?)`.
The compiler proves eligibility from its data reads; returning a page-shaped
object from an arbitrary handler is not proof of watchability.
For a complete consumer, use [the React screen](/docs/v4/react-query-basic).

| Argument/result            | Contract                                         |
| -------------------------- | ------------------------------------------------ |
| `input`                    | Same exact input as the one-shot Query.          |
| `onValue(value, delivery)` | Receives the complete decoded authorized result. |
| `options.signal`           | Optional caller cancellation.                    |
| `options.onStateChange`    | Connection/reconnection state notification.      |
| `options.onError`          | Terminal typed watch failure.                    |
| Return value               | Function that stops the watch.                   |

Delivery is `initial`, `update`, or `reset`. Reset reasons include
`authority-changed`, `deployment-changed`, and `resume-unavailable`.
Replace the displayed result on every successful delivery, including removed
rows and omitted fields. Do not merge it as an entity patch.

## Authorization and recovery

Relevant committed changes cause recomputation with fresh Context and Policy.
The Runtime tracks reads, relation membership, ordering boundaries, and Policy
evidence. A failed recomputation publishes no partial result.
Separate Queries do not publish one atomic combined snapshot.

The transport uses multiplexed SSE downstream and Fetch/POST upstream.
After reconnect, an opaque compatible Resume Token can resume retained work;
otherwise the server sends a complete authorized reset. A token is not authority.
No sticky-session routing is needed across compatible instances.

On logout or a credential change, stop old watches and create a fresh client
scope. Terminal authorization/protocol failures require recovery of that scope;
there is no fallback polling loop. Cancellation or stopping a watch does not
undo an already committed Mutation.

| Limit                        | Bound |
| ---------------------------- | ----- |
| Active watches per Principal | 64    |
| Dependency tokens per plan   | 256   |
| Complete result              | 1 MiB |

Live infinite lists and offline/persistent resume are not available.
The [Query Resource](/docs/v4/reactive-query-resources) wraps a watch for
framework-neutral state; [React Query](/docs/v4/react-query) uses native cache ownership.
