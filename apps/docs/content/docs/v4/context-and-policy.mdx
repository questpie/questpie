Import `defineContext`, `context`, `principal`, `definePolicy`, `policy`, and
`expr` from `questpie`. Start with [Auth and permissions](/docs/v4/auth) for the
identity-provider flow and [the data chapter](/docs/v4/data-and-queries) for
complete Context and Policy declarations.

## defineContext

`defineContext({ name, input, resolve })` declares the application's Context.
`input` is a Codec. `resolve` derives immutable `tenant` and `values` from
validated input, the Principal, and bounded bootstrap reads.
`context.tenant({ id })` constructs the Tenant value.

Resolution runs once per root execution; nested work inherits it. It cannot
write data, run external Services, open SQL, or grant System Authority.
Bootstrap access is bounded read-only exact-key lookup, not unrestricted data
access. Context convenience values cannot replace current membership evidence.

## Principal

`principal.anonymous()` represents no authenticated identity.
`principal.user({ id })` and `principal.service({ name })` construct trusted
identity values for host code. Their constructors authenticate nothing.
Never accept one of these values from a public request body as trusted identity.

## definePolicy

`definePolicy(collection, { name, ...rules })` attaches authorization to one
Collection. Missing permission fails closed.

| Rule                                              | Purpose                                                    |
| ------------------------------------------------- | ---------------------------------------------------------- |
| `read.admit`                                      | Admit the read, for example with `policy.authenticated()`. |
| `read.rows`                                       | Select the rows the caller may see.                        |
| `create.admit`, `create.candidate`                | Admit creation and authorize the complete candidate.       |
| `update.admit`, `update.rows`, `update.candidate` | Admit an update and authorize current and candidate rows.  |
| `delete.admit`, `delete.rows`                     | Admit deletion and authorize the target rows.              |
| `fields`                                          | Set supplied-input and selected-output field permissions.  |

Use the capability-checked `expr` vocabulary in row/field rules. `expr.always()`
permits that phase; it does not skip other phases. `policy.public()` admits
anonymous callers. `policy.authenticated()` requires an authenticated Principal,
but does not prove membership in a shop.

Policy-only `expr.exists` performs bounded boolean membership/evidence reads.
It cannot return evidence rows or expose their count. Use current relational
evidence when roles or membership can change; a client-provided role is not
permission. Query filters cannot use Policy-only expression capabilities.

## Enforcement and nondisclosure

Framework data operations apply row Policy in SQL before key lookup, ordering,
cursor boundaries, limit, lock, and disclosure. After a write waits for a row
lock, it rechecks current authority and candidate state. Trusted `values`
bypass only caller field input authority.

A missing and an invisible keyed row produce the same not-found result.
Direct execution, generated clients, workers, and live recomputation use the
same rules. Policy does not generate PostgreSQL RLS. Independently issued SQL
has none of these framework guarantees.

## Client lifetime

`client.withContext(input)` creates an immutable scope, not a session.
On a credential or Context change, release the old subscriptions/cache and
create a fresh scope. With React, await adapter `dispose()` before binding the
replacement. Equal user and tenant IDs do not make old credentials current.
