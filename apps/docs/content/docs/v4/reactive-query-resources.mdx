Call `scope.queries[qualifiedName].observe(input)` to obtain the latest complete
result of a compiler-proven watchable Query. For React use
[the native adapter](/docs/v4/react-query) instead of feeding a second cache.

These pages document QUESTPIE 4.0.0-beta.2.

| Member                         | Contract                                                                             |
| ------------------------------ | ------------------------------------------------------------------------------------ |
| `observe(input)`               | Validates input and returns the canonical resource for that input inside this scope. |
| `resource.getSnapshot()`       | Frozen current snapshot, stable until state changes.                                 |
| `resource.subscribe(listener)` | Subscribe to changes; returns unsubscribe.                                           |

The snapshot is `pending`, `ready` with `value`, or `failed` with a closed
failure. Pending/ready snapshots also report connection state. The first
subscriber starts one watch; later subscribers share it. The last unsubscribe
stops it. A later subscriber can reopen an idle resource.

`initial`, `update`, and `reset` deliveries replace the complete result.
During a retryable carrier reconnect, the resource can retain only already
disclosed data inside the same Context scope. Terminal failure clears output.
Call `observe` again for a fresh resource after resolving the failure.

Resources are partitioned by immutable client scope. Equal Context values in
different scopes share nothing. On a credential change, unsubscribe and create
a fresh scope. Credentials are owned by the application's Auth integration.

There are at most 128 resource identities per scope. This abstraction adds no
Mutation invalidation, polling fallback, offline persistence, or normalized
entity store. Use [Live Query reference](/docs/v4/realtime) for transport limits.
