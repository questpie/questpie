QUESTPIE v4 keeps one implementation kernel where semantics agree and exposes
only the capabilities valid for each job. Public names tell you which contract
owns the value.

## Build values once

Use `codec.*` for Operation input and output, Context input, and durable
payloads:

```ts
import { codec, defineCollection, field } from "questpie";

const messageId = codec.uuid();

export const messages = defineCollection({
	name: "messages",
	fields: {
		id: field.uuid({ default: "randomUuid" }),
		body: field.text(),
	},
});
```

`codec.uuid()` and `field.uuid()` share scalar identity and validation. A Field
adds database-only behavior such as nullability, defaults, and column mapping.
`value.*` retains the compatible embedded-JSONB vocabulary. Operation does not
define a second `operation.uuid()` grammar.

## Choose the owner of application work

| Work                                           | Owner       | Boundary                                                               |
| ---------------------------------------------- | ----------- | ---------------------------------------------------------------------- |
| Canonicalize caller input without I/O          | `normalize` | Closed pure program inside the owning Operation lifecycle              |
| Supply a trusted server value                  | `values`    | Closed assignment from input or immutable Execution facts              |
| Read or derive an authorized result            | Query       | One Policy-aware read snapshot                                         |
| Decide whether a principal may perform work    | Policy      | Pure authorization decision over explicit subject, resource, and facts |
| Validate application state or write atomically | Mutation    | One PostgreSQL transaction, including audit and durable acceptance     |
| React to one exact committed fact              | Reaction    | Durable committed-fact causation with no independent producer          |
| Observe a changing authorized read             | Live Query  | Re-evaluated Query result driven by committed invalidation             |

Reaction is the committed-fact authoring meaning over the internal durable
kernel. QUESTPIE does not expose a general lifecycle hook catalogue.

## Import executable factories from the current contract

```ts
import { codec } from "questpie";
import { defineMutation, defineQuery } from "#questpie/app";

export const messageById = defineQuery({
	name: "messages.byId",
	input: codec.object({ id: codec.uuid() }),
	handler: ({ input, ctx }) => ctx.data.messages.get({ key: input }),
});

export const renameMessage = defineMutation({
	name: "messages.rename",
	input: codec.object({ id: codec.uuid(), body: codec.text() }),
	handler: ({ input, ctx }) =>
		ctx.data.messages.update({
			key: { id: input.id },
			patch: { body: input.body },
		}),
});
```

`#questpie/app` also exports `defineReaction`. Each factory has its own exact
context; there is no universal Definition builder. Packages import the same
names from their generated `#questpie/package` contract and cannot see
host-only Resources.

Generated server Operation maps use nested calls such as
`ctx.mutations.delivery.sendMessage`. Canonical Resource Identity and direct
client/App maps retain exact `<kind>:<qualified-name>` keys. QUESTPIE reports
`QP-COMPOSE-023` when one same-kind Operation would be both a callable leaf and
a namespace. It reports `QP-COMPOSE-024` when a final `then` segment would make
the generated namespace Promise-like.

Server capability maps are frozen objects with no inherited Object helpers.
Names such as `constructor` and `prototype` are ordinary generated members.
Treat the map as a typed capability surface, not as a general JavaScript object.

## Watch Queries

A supported generated Query method gains `.watch` and returns complete freshly
authorized results. Watching does not bypass Policy: every recomputation is
authorized again.
