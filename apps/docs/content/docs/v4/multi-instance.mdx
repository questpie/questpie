---
title: Run multiple instances without optional authority
description: Scale requests, realtime, and durable workers while PostgreSQL remains the only durable source of truth.
kind: guide
---

QUESTPIE is correct with ten compatible Runtime instances by default. Any
instance can accept a request, client POST, realtime reconnect, or durable
claim. No application leader, queue leader, process registry, or
sticky-session correctness is required.

PostgreSQL owns every fact that must survive a crash. Correctness needs
PostgreSQL and nothing else: no external cache, queue, or delivery service
takes part in a Context, Policy, Query result, or durable decision.

## Route any request to a compatible instance

Application Services live once per Runtime instance. Execution Services live
once per root. Neither is a cluster singleton.

Mutation call receipts, Change Ledger frontiers, and durable runs and leases
live in PostgreSQL. A crashed Runtime loses only its local roots, connections,
buffers, and Services. Another instance can reclaim expired work or resume the
client.

During a rolling deployment, an instance claims only work whose pinned
executable bytes it carries. Old and new compatible builds may overlap.
Nonterminal runs and retained Resume Tokens can block retirement when they
still require the old bytes.

## Use one multiplexed realtime transport

QUESTPIE uses one bounded SSE downstream per client scope and Fetch/POST
upstream. The SSE connection may carry several Live Query bindings:

```text
browser -- SSE --------------------------> Runtime A
browser -- Mutation POST ---------------> Runtime B
browser -- reconnect + opaque token ----> Runtime C
                                               |
                                               v
                                          PostgreSQL
```

Runtime A can disappear after the POST commits. Runtime C reconciles
PostgreSQL and either resumes retained compatible state or sends a complete
freshly authorized reset. Sticky routing can reduce reconnects, but it grants
no stronger guarantee.

## Inspect the same operational truth

Health, CLI, Studio, and telemetry consume the accepted Execution Envelope and
canonical Runtime state. They can show connection reset, claims, and executable
compatibility without exposing credentials, raw Context, Policy evidence,
payloads, or database URLs.

The Index contract is B-tree-only, and QUESTPIE emits no RLS claim.
