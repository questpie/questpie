Add the write operation used by the Barbershop staff form. A Mutation owns one
PostgreSQL transaction, so a failed write does not leave a partial change.
Start with the complete [data chapter](/docs/v4/data-and-queries).

## Allow exactly the intended edit

Replace `src/data/policies.ts` with this version. Read access stays the same.
The update rule admits authenticated callers and allows them to supply only
`summary`. It does not allow a caller to change the ticket ID.

```ts title="src/data/policies.ts"
import { definePolicy, expr, policy } from "questpie";
import { comments } from "./comments";
import { tickets } from "./tickets";

export const ticketPolicy = definePolicy(tickets, {
	name: "tickets.default",
	read: {
		admit: policy.authenticated(),
		rows: () => expr.always(),
	},
	update: {
		admit: policy.authenticated(),
		rows: () => expr.always(),
		candidate: () => expr.always(),
	},
	fields: {
		update: () => ({ summary: expr.always() }),
	},
});

export const commentPolicy = definePolicy(comments, {
	name: "comments.default",
	read: {
		admit: policy.authenticated(),
		rows: () => expr.always(),
	},
});
```

## Define the Mutation

Create this file. `createInput().pick(...)` derives required ID and summary
codecs from the Collection; it does not choose which database action runs.
The handler explicitly updates the ticket.

```ts title="src/mutations/rename-ticket.ts"
import { codec, operation, policy } from "questpie";
import { defineMutation } from "#questpie/app";
import { tickets } from "../data/tickets";

export const renameTicket = defineMutation({
	name: "tickets.rename",
	network: true,
	input: tickets.createInput().pick({ id: true, summary: true }),
	output: codec.object({}),
	policy: policy.authenticated(),
	errors: {
		ticketUnavailable: operation.error({
			code: "TICKET_UNAVAILABLE",
			status: 404,
		}),
	},
	handler: async ({ input, ctx, errors }) => {
		const ticket = await ctx.data.tickets.update({
			key: { id: input.id },
			patch: { summary: input.summary },
		});
		if (ticket === null) throw errors.ticketUnavailable();
		return {};
	},
});
```

Run `bun run build` and `bun run types:check` again. The generated client gains
`mutations["tickets.rename"]`, with required `id` and `summary` input.

A successful call returns `{}` after the summary update commits. A missing or
invisible ticket raises the declared `TICKET_UNAVAILABLE` error with status 404.
An empty or overlong summary fails the Field-derived input contract. Transport
failures are separate from declared business errors.

## Keep transaction work inside the Mutation

Use `patch` for caller-supplied edits. A named Mutation can also provide trusted
server-owned `values`; the complete candidate still passes Policy and validation.
Neither lane grants System Authority.

Keep email, payment, and object-store requests outside the transaction. Use
an [Action or durable Job](/docs/v4/custom-logic) for those effects. If the caller
loses a response, do not assume the transaction rolled back. Recover with the
same Call Identity; a new identity can perform another write.

Continue with [the generated client](/docs/v4/clients). The
[Operation reference](/docs/v4/executable-definitions) covers exact members,
lifecycle ownership, and error behavior.
