Import `defineService` from `questpie`. A Service owns a runtime dependency,
such as the Barbershop Auth provider. It is not serialized Context or durable state.
Use [Auth](/docs/v4/auth) or [custom logic](/docs/v4/custom-logic) for task guidance.

## defineService

| Member                         | Contract                                                                         |
| ------------------------------ | -------------------------------------------------------------------------------- |
| `name`                         | Required stable qualified name.                                                  |
| `lifetime`                     | Required `application` or `execution`.                                           |
| `effect`                       | Required `read` or `external`.                                                   |
| `dependencies`                 | Optional named map of other Services.                                            |
| `create({ services, signal })` | Required factory; return the inferred instance, synchronously or asynchronously. |
| `dispose(instance)`            | Optional cleanup; may return a Promise.                                          |

An application Service is created lazily once per Runtime instance.
An execution Service is created lazily once per root execution. Concurrent
consumers share creation. Cleanup runs once in reverse dependency order after
success, failure, cancellation, or the end of an owned response stream.

## Dependency constraints

The compiler rejects cycles. An application Service cannot depend on an
execution Service. A `read` Service cannot depend on an `external` Service.
Queries and Mutations cannot hide external effects through dependencies.
An Action’s external Service must have `lifetime: "execution"`; use the
application lifetime for the credential resolver’s provider instead.
Creation does not silently retry provider work.

The generated handler context exposes the Services allowed for that execution
kind. Application lifetime does not mean a cluster singleton. Service instances
are excluded from Context, artifact data, durable rows, and safe telemetry.

## Credential resolver

`defineCredentialResolver({ name, service, resolve })` takes one application
Service with `effect: "external"`. Its resolver receives `{ request, service }`
and returns an anonymous, malformed, unavailable, or resolved-Principal outcome.
It verifies credentials; it does not decide data Policy or grant System Authority.
